Abstract

This document specifies the Theater Showtimes General Application Profile v2.0.0 (TS-GAP), a general application profile of the Culture Information Model (Culture IM / DRK IM) version 2.0.0, for describing theater showtimes metadata in the German Culture Dataspace (Datenraum Kultur, DRK). The profile defines how classes, properties, and controlled vocabularies of the Culture (DRK) Ontology [[DRK-ONTOLOGY]] and selected external vocabularies are combined and constrained to describe theater organizations, theatrical productions, theatrical events/showtimes, venues and their accessibility, roles, characters, performers, offers, prices, datasets, distributions, and data services.

The profile reuses Schema.org [[SCHEMA-ORG]] as a foundational vocabulary, integrates DCAT [[vocab-dcat-3]] and Dublin Core Terms for dataset, distribution, and data-service metadata, and reengineers concepts from A11yJSON [[A11YJSON]] for describing accessibility features of places. Conformance is expressed through application-profile cardinalities and can be operationalized using SHACL [[shacl]] shapes.

Introduction

Context

The Culture (DRK) Ontology is the semantic backbone of the Culture Information Model. It provides modular vocabulary support for organizations, places and accessibility, creative works, events, roles, data services, and domain-specific theater-showtimes metadata. TS-GAP constrains and documents the theater-showtimes subset for consistent metadata provisioning in dataspaces.

Scope and application-profile methodology

The DRK IM is developed following an AP-first methodology. TS-GAP is a General Application Profile: it defines a common minimum, reusable set of terms and constraints for theater showtimes metadata. More provider- or service-specific application profiles may derive from TS-GAP by narrowing these constraints, adding locally required details, or documenting implementation-specific rules.

TS-GAP focuses on metadata for discovering and interpreting theater showtimes data. Access- and usage-policy modeling is supported by the wider Culture IM but is outside the scope of this profile.

Conformance

An RDF graph conforms to TS-GAP if, for every entity typed with a class defined or reused by this profile, it satisfies the cardinality and value constraints stated in the corresponding class/property table and uses the specified controlled vocabularies where required. Cardinalities are written as min..max, where * denotes an unbounded maximum.

ObligationCardinalityMeaning
mandatory1..1, 1..*The property MUST be present at least once.
recommended0..1, 0..*The property SHOULD be provided where the information is available.
optional0..1, 0..*The property MAY be provided.
conditionalcondition-specificPresence depends on the condition stated in the class section.

The obligation labels are derived from the mandatory/recommended/optional grouping in the draw.io model. For machine validation, these constraints should be translated into SHACL shapes.

Conceptual model

TS-GAP separates theatrical productions from theatrical events. A theatrical production represents the produced/staged work, while a theatrical event represents one showtime of that work. Events take place at physical or virtual locations and can carry ticket offers. Theater organizations are linked to their productions, events, and data services. Venue accessibility is modeled through place accessibility features, animal policies, and wheelchair-place descriptions.
